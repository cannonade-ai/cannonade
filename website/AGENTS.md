# AGENTS.md — website

This directory is the Cannonade website: the landing page at `/` and the documentation.
It is a **separate npm project** from the Electron app in the repository root. Do not add it
to a workspace, and do not run root scripts from here.

## Stack

Astro + Starlight. No UI framework is installed — everything is `.astro`, plain CSS, and
markdown. Add Vue (`npx astro add vue`) only if a component genuinely needs client-side
state; do not add React.

## Commands

```bash
npm install
npm run dev     # local dev server
npm run build   # static output to dist/ — this is the check to run before committing
```

There is no typecheck or lint step here. `npm run build` is the validation.

## Layout

```
src/
  pages/index.astro        landing page (owns "/")
  layouts/                 landing page shell
  components/landing/      landing sections, prefixed Landing*
  components/              Starlight component overrides
  content.config.ts        prefixes every docs route with /docs/
  content/docs/
    guides/                task-oriented pages, served at /docs/guides/*
    reference/             lookup pages, served at /docs/reference/*
  styles/
    fonts.css              @font-face rules for the vendored fonts
    tokens.css             shared palette and type tokens
    docs.css               Starlight theming
    landing.css            landing page styles
public/fonts/              vendored woff2 files, latin subsets only
  config/site.ts           repo URLs, download targets, app version
```

## Rules

- No comments in code.
- Return type annotations on all functions in `.ts` files.
- Component filenames are PascalCase; `.ts` filenames are kebab-case.
- Landing section components are prefixed `Landing*` and live in `components/landing/`.
- Colors and fonts come from `src/styles/tokens.css`. Never hardcode a hex value in a
  component or in `landing.css` — add a token.
- The landing page is dark only and deliberately so. The docs support light and dark, and
  default to dark for first-time visitors via the `ThemeProvider` override.
- Docs pages are markdown. Adding a page means adding a file under `guides/` or
  `reference/` with `title`, `description`, and `sidebar.order` frontmatter — the sidebar
  is autogenerated, so no config change is needed.
- Docs are served under `/docs/`, but the files do **not** live in a `docs/docs/` folder.
  The prefix is added by `generateId` in `src/content.config.ts`. Two consequences:
  internal links must be written with the prefix (`/docs/guides/quick-start/`), while
  `autogenerate: { directory: ... }` in `astro.config.mjs` matches the **on-disk**
  directory and must stay unprefixed (`guides`, not `docs/guides`).
- `/docs/` is a real page, `src/content/docs/index.md`. Keep its link lists in sync when
  adding or removing a guide.

## Fonts

Fonts are vendored as woff2 files in `public/fonts/` rather than pulled from an npm
package, so that `src/styles/fonts.css` can own the `@font-face` rules. Two things depend
on that and must stay true:

- `font-display: optional` on every face. Combined with the preloads, a page either paints
  with the real font or keeps the fallback for that page view — it never swaps mid-render,
  which is what caused visible flicker before.
- Every face is preloaded by `src/components/FontPreloads.astro`, which is rendered into
  both the landing page `<head>` and the Starlight `Head` override. Adding a font means
  adding it in three places: the file, the `@font-face` rule, and the preload list.

The files are the `latin` subsets from the Fontsource packages `@fontsource/saira-condensed`
and `@fontsource-variable/ibm-plex-sans`. To update, install the package temporarily and
copy from its `files/` directory.

Only two families are vendored: Saira Condensed for display and IBM Plex Sans for
everything else. `--cn-mono` is a system stack with no downloaded file, and is used only
for docs code blocks — never for landing page or UI text.

Note that `npm run dev` injects styles through JavaScript and will always flicker a
little. Judge rendering with `npm run build && npm run preview`.
- Images on the landing page are currently `placehold.co` placeholders. Replace them with
  real screenshots; keep the `width`/`height` attributes so layout does not shift.
